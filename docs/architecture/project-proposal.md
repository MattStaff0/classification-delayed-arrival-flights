1. What data mining problem will you study, and why does it matter?
   The data mining problem our team will study is the classification of a scheduled flight arriving at its destination on time or a scheduled flight arriving at its destination late. According to the Bureau of Transportation Statistics, a flight is considered delayed when it arrives 15 minutes or more after the schedule[1]. This problem is highly relevant to US air travel: in June 2026, 73% of scheduled flights were on time; diverted and canceled flights are counted in total and categorized as not on time [1]. Passengers will use this model at booking time to decide which flights to buy. The model input would be scheduled information such as the flight carrier, route, and departure hour. The model output would be the probability that a scheduled flight will arrive late, which will then be classified as on time or delayed using a threshold value.
2. What dataset will you use, and can you access it now?
   This project will use a dataset from the Bureau of Transportation Statistics. The database name is “Airline On-Time Performance Data”; the database table we are pulling data from is “Reporting Carrier On-Time Performance (1987 - present)”. The data we intend to use spans a full year, from July 2025 to June 2026. The data is currently accessible and already downloaded. One example of the data we will use is a completed, non-diverted scheduled flight. Across the 12 months of data, we have 7,043,316 raw records, with 6,896,283 usable records matching our criteria for an instance. The attributes we plan to use are everything known at booking time, such as flight carrier, origin airport, destination, scheduled times, distance, and month. We are discarding anything post-departure. This is a public US government dataset with no restrictions on access and use.
3. What data mining method will you test, and what will serve as the baseline?
   The baseline we are using is logistic regression, as this classification algorithm is simple and interpretable and uses a linear model. The data mining method we are going to test is Gradient Boosting. Both of these models use the same features. The controlled comparison that we will run is a model that has access to historical records, such as the origin airport and departure hour, to derive a feature that gives the late arrival rate from the training data plus the base attributes, and a model that only has the base attributes.
4. How will you evaluate success while avoiding data leakage?
   We will evaluate success by comparing the logistic regression model’s F1-Score and PR-AUC against the Gradient Boosting model’s. Delayed flights make up 22.4% of our dataset, making them the minority class. Because of this, a model could predict that most flights will arrive on time and still have a high accuracy. To evaluate the model accurately, we will use PR-AUC, or the area under the precision-recall curve, which lets us assess whether the model can predict delayed flights while balancing false positives against false negatives [4]. Additionally, we will use F1-score, which considers precision and recall [2]. To avoid data leakage, we will remove all features unknown at booking time, such as arrival time, weather delay, delayed departure, and late aircraft delay. Including these features would give the model information about the flight outcome that would not be available during booking time. Our training split is from July 2025 to March 2026, the validation split is in April 2026, and the testing split is from May 2026 to June 2026. We select the classification threshold on our validation split. The floor for our PR-AUC is .236 which comes from the number of late flights divided by the total number of flights from our testing split.
5. Why is the project feasible within the semester and available computing resources?
   This project is feasible within the semester because we already have the data downloaded and verified, and the methods we plan to use are standard library implementations. The current dataset is 3GB and includes all columns, and Google Colab offers 12.7GB of RAM, which easily fits the entire dataset in memory. Furthermore, the actual data that the model will use to train, validate, and test is much smaller. Lastly, the ablation is one additional training run using the same model and data. The only cost for this ablation is calculating the late rates from the training data months.
